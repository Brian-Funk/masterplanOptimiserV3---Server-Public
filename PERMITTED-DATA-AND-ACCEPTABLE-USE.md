# Permitted data and acceptable use

## Intended use

Use Masterplan only for information needed to create, publish and operate an
event schedule, administer access, and send closely related operational
communications.

Normally permitted information includes:

- a participant's operational display name and event assignment;
- an email address when the controller enables activation email;
- working times, availability and schedule assignments;
- purpose-specific task instructions, public descriptions and locations;
- passkey public material and security metadata needed for authentication; and
- minimised security, audit and deletion-workflow records.

## Unsupported information

Do not enter health, dietary, disability, safeguarding, political, religious,
trade-union, sexual-life, disciplinary, criminal-allegation, identity-document
or unrelated private information. Do not use free-text fields to build profiles
about participants. The supported release does not enable sensitive-data
processing merely because a text field can technically contain text.

Optional fields must have a documented operational purpose. Collect only what
is necessary for that purpose and remove it when it is no longer needed.

## Visibility

Information shown to participants must be limited to their operational
schedule. Public schedule links must contain only deliberately public schedule
content. Organiser-only information must never become public or enter a
participant's offline cache merely because it exists in a published payload.

Authorised editors must acknowledge the current instance policy before broad
calendar editing. This is an operational acknowledgement. It is not consent,
does not waive rights and does not authorise sensitive-data processing.

The controller remains responsible for checking its desktop source data,
field definitions, integrations and exports before publication.
